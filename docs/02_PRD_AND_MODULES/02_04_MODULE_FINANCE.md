# 02_04 — Модуль «Финансы»

> Slug модуля: `finance`.
> Frontend: `frontend/src/app/(dashboard)/finance/page.tsx`, `frontend/src/components/finance/`, `frontend/src/lib/finance/`.
> Backend: `backend/src/modules/finance/`.
> Контракт API: `docs/03_API_CONTRACTS/03_03_REPAIRS_AND_FINANCE_API.md`.

---

## 1. Область

Управленческий учёт: кассы и счёты, движение денег, переводы между своими счетами, счета на оплату по форме РФ, отчёт о прибылях и убытках. Модуль подключаемый: без установки `finance` страницы скрыты, API отвечает `403 MODULE_NOT_INSTALLED`.

---

## 2. Маршрут

`/finance` — `app/(dashboard)/finance/page.tsx`, обёрнут в `<Guard requiredPermission="finance:read" requiredModule="finance">`.

Структура страницы: KPI-карточки, карточки балансов счетов, три вкладки.

| Вкладка | Компонент |
|---|---|
| Транзакции | `TransactionsTable.tsx` |
| Счета на оплату | таблица внутри страницы |
| Отчёт P&L | `ProfitLossView.tsx` |

KPI: выручка за период, расходы, чистый P&L (`emerald` при положительном значении, `rose` при отрицательном).

## 3. Кассы и счёты

Таблица `cash_accounts`: название, валюта, баланс, признак основной.

Компонент `BalanceCards.tsx` показывает балансы с иконками по типу счёта (касса, банковский счёт, эквайринг).

Создание счёта — `POST /api/v1/finance/accounts` с начальным балансом.

---

## 4. Перевод между счетами

Компонент `TransferModal.tsx`, эндпоинт `POST /api/v1/finance/accounts/transfer`.

Правила (`backend/src/modules/finance/finance.service.ts`):

1. Счёт-источник и счёт-получатель должны различаться (проверка в Zod-схеме).
2. Оба счёта блокируются `SELECT … FOR UPDATE` внутри одной транзакции.
3. Валюты должны совпадать — межвалютные переводы не поддерживаются (`400 VALIDATION_ERROR`).
4. Баланса источника должно хватать, иначе `409 INSUFFICIENT_FUNDS`.
5. Балансы изменяются одним движением, дополнительно создаются две записи в `transactions`: расход по источнику и доход по получателю с категорией `Internal transfer`.

Перевод атомарен: при любой ошибке транзакция откатывается целиком.

## 5. Транзакции

Таблица `transactions`. Направление — `income` или `expense` (поле `direction`).

Состав записи: счёт, категория (`category_id` и текстовое `category_name`), сумма, валюта, описание, контрагент с ИНН, дата операции, привязки к сделке, заказ-наряду или счёту.

Создание — `POST /api/v1/finance/transactions`. Проверки:

- валюта операции должна совпадать с валютой счёта;
- при расходе баланс не может уйти в минус (`409 INSUFFICIENT_FUNDS`);
- баланс счёта обновляется в той же транзакции, что и вставка записи.

Компонент `CreateTransactionModal.tsx` — выбор кассы, статьи, суммы и привязки к сущности.

Справочник статей — `finance_categories` с самоссылкой `parent_id` для иерархии. Типовые статьи: оплата ремонта, продажа запчастей, аренда, зарплата, закупка, реклама.

## 6. Счета на оплату

### Номер

Формат `СЧ-YYYY-NNNN`. Уникальность — индекс `idx_invoices_number_tenant (tenant_id, invoice_number)`.

### Расчёт сумм

Считает сервер, клиентские значения итогов не принимаются:

```
позиция.total = quantity × unit_price
subtotal      = Σ позиция.total
vat_amount    = subtotal × vat_rate / 100
total         = subtotal + vat_amount
```

Ставка НДС по умолчанию 20, допустимый диапазон 0–100.

### Статусы

`draft` → `sent` → `paid`, плюс `overdue` и `cancelled`. Созданный через API счёт сразу получает статус `sent`.

### Позиции

Таблица `invoice_items`, поле `source`: `manual`, `repair_work`, `repair_part`, `deal`; `source_label` хранит человекочитаемую ссылку на источник (например номер наряда).

### Создание из ремонта

`POST /api/v1/invoices/from-repair/:repairId`:

1. Проверяет существование наряда в пределах арендатора.
2. Каждая работа наряда становится позицией с `source = repair_work`, каждая запчасть — с `source = repair_part` и своим количеством.
3. Если ни работ, ни запчастей нет, создаётся одна позиция по `estimated_cost`.
4. Реквизиты плательщика по умолчанию берутся из данных клиента наряда.
5. Счёт связывается с нарядом полем `repair_order_id`.

### Оплата

`POST /api/v1/invoices/:id/pay` в одной транзакции:

1. Блокирует счёт `FOR UPDATE`; повторная оплата — `409 INVOICE_ALREADY_PAID`.
2. Проверяет существование кассы и совпадение валюты со счётом.
3. Ставит статус `paid`, заполняет `paid_at` и `paid_account_id`.
4. Увеличивает баланс кассы на сумму счёта.
5. Создаёт входящую транзакцию с категорией `Invoice payment` и привязками к счёту, наряду и сделке.

### Печатная форма

Компонент `InvoiceViewModal.tsx`: реквизиты, таблица товаров и услуг, итоги, разбивка НДС, **сумма прописью** (`frontend/src/lib/finance/amount-to-words.ts` — рубли и копейки по правилам русского языка), кнопки печати и отправки в чат.

Компонент создания — `InvoiceCreateModal.tsx`: выбор компании с автозаполнением реквизитов, редактор позиций, переключатель НДС, предпросмотр итогов.

## 7. Отчёт P&L

Эндпоинт `GET /api/v1/finance/pnl?from=…&to=…`. По умолчанию период — последние 30 дней.

Агрегация в SQL: `GROUP BY direction, category_name`. Ответ содержит суммы доходов и расходов, чистую прибыль и разбивку по статьям с долей каждой статьи в процентах (округление до одного знака).

Компонент `ProfitLossView.tsx` показывает структуру доходов и расходов полосами с процентами и свод по рентабельности. Дополнительно на `/analytics` есть график `PnlChart.tsx` (Recharts).

## 8. Права

| Действие | Требования |
|---|---|
| Чтение счетов, транзакций, P&L, инвойсов | модуль `finance` + `finance:read` |
| Создание счёта, перевод, транзакция, инвойс, оплата | модуль `finance` + `finance:write` |

Право `finance:admin` объявлено в модели прав, но отдельных эндпоинтов под него пока нет.
