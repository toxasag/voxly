# 02_05 — Модуль «AI-боты»

> Slug модуля: `ai_bots`.
> Frontend: `frontend/src/app/(dashboard)/modules/ai-bots/`, `frontend/src/components/ai-bots/`, `frontend/src/lib/ai-bots/`, `frontend/src/lib/api/use-bots.ts`, `use-bot-chat.ts`.
> Backend: не реализован (задачи M4.2.*).

---

## 1. Область

Настройка AI-ассистентов, шаблоны промптов с подстановкой данных CRM, чат со стриминговым ответом, учёт расхода токенов и стоимости.

Модуль подключаемый: без установки `ai_bots` страницы скрыты.

**Состояние:** frontend реализован полностью и работает на мок-данных. Backend отсутствует — нет таблиц `ai_bots`, `ai_prompt_templates`, `ai_logs`, нет SSE-эндпоинта и слоя абстракции провайдеров. Поэтому в `docs/03_API_CONTRACTS/` контракта для этого модуля пока нет.

## 2. Маршруты

| Маршрут | Файл | Назначение |
|---|---|---|
| `/modules/ai-bots` | `modules/ai-bots/page.tsx` | сетка ботов, поиск, фильтр статуса |
| `/modules/ai-bots/[id]` | `modules/ai-bots/[id]/page.tsx` | три вкладки: чат, промпт, использование |
| `/settings/ai` | `settings/ai/page.tsx` | настройки единого AI-агента и баланс токенов |

Обе страницы модуля обёрнуты в `<Guard requiredPermission="ai_bots:read" requiredModule="ai_bots">`; действие «Configure» дополнительно требует `ai_bots:configure`.

## 3. Модель бота

`frontend/src/lib/ai-bots/ai-bots.types.ts`:

| Поле | Смысл |
|---|---|
| `name`, `description` | название и описание |
| `accent` | цвет аватара: `amber`, `sky`, `emerald`, `orange`, `rose` |
| `model` | модель из каталога |
| `status` | `active` или `paused` |
| `mode` | `suggester`, `autoreply`, `disabled` |
| `temperature` | 0–1 |
| `max_tokens` | 128–8192 |
| `system_prompt` | системный промпт с переменными |
| `context_entities` | какие сущности CRM подмешивать в контекст |
| `tokens_used`, `tokens_limit` | расход и лимит |
| `requests_count`, `avg_latency_ms`, `cost_rub` | статистика |
| `last_used_at` | последнее использование |

**Режимы работы:**

| Режим | Поведение |
|---|---|
| `suggester` | AI готовит черновик, менеджер проверяет и отправляет |
| `autoreply` | AI отвечает клиенту в чате сделки автоматически |
| `disabled` | бот настроен, но не срабатывает |

**Контекстные сущности:** `contacts`, `companies`, `deals`, `tasks`, `repairs`, `invoices`. Данные должен подставлять сервер в границах арендатора.

## 4. Каталог моделей

`MODEL_CATALOG` — модель, провайдер, размер контекстного окна, цена за 1000 входных и выходных токенов:

| Модель | Провайдер | Контекст |
|---|---|---|
| `gpt-4o` | OpenAI | 128 000 |
| `gpt-4o-mini` | OpenAI | 128 000 |
| `claude-sonnet-4` | Anthropic | 200 000 |
| `claude-opus-4` | Anthropic | 200 000 |
| `deepseek-v3` | DeepSeek | 64 000 |
| `gemini-1.5-pro` | Google | 1 000 000 |

Функция `estimateCost(model, tokensIn, tokensOut)` считает стоимость в рублях.

По правилам проекта вызовы LLM должны идти через слой абстракции провайдеров, без прямых `fetch` к OpenAI или Anthropic из кода приложения.

## 5. Шаблоны промптов

Компонент `PromptTemplateEditor.tsx`, схемы `frontend/src/schemas/ai-prompt.schema.ts`.

**Переменные** в синтаксисе `{{entity.field}}`. Поддерживаемый набор (`PROMPT_VARIABLES`): `tenant.name`, `user.name`, `contact.name`, `contact.phone`, `company.name`, `deal.title`, `deal.budget`, `repair.ticket_number`.

Возможности редактора:

- палитра переменных — вставка в позицию курсора, использованные подсвечиваются;
- счётчик токенов с полосой относительно контекстного окна выбранной модели (`estimateTokens` — примерно 4 символа на токен);
- режим предпросмотра: переменные заменяются примерными значениями (`renderPromptPreview`);
- предупреждение о неизвестных переменных (`findUnknownVariables`) — такие токены уйдут в модель как есть.

Шаблоны должны храниться в БД, а не в коде. Сейчас на frontend лежат три примера в `mock-ai-bots.ts`; вкладка «Промпт» позволяет применить шаблон к боту.

## 6. Чат и стриминг

Компоненты `BotChat.tsx` и `BotChatInput.tsx`, состояние — `frontend/src/lib/api/use-bot-chat.ts`.

**Источники сообщений:** `human`, `ai`, `system`, `ai_bot` — совпадают с моделью таймлайна.

**Интерфейс чата:** пузыри с аватаром, именем, временем, бейджем источника; для ответов бота — количество токенов и задержка; индикатор набора текста во время стриминга; системные сообщения отдельным компактным стилем.

**Ввод:** авторастущее поле, счётчик символов (лимит 4000) и токенов, отправка по Enter, перевод строки по Shift+Enter, кнопка остановки генерации во время стрима.

**Управление:** остановка (частичный ответ сохраняется), перегенерация последнего ответа, очистка переписки.

**Обработка обрыва:** баннер ошибки с кнопкой перегенерации. Для проверки этого пути промпт с префиксом `/fail` детерминированно обрывает поток.

**Текущая реализация:** ответ выдаётся чанками по таймеру из набора заготовленных текстов. Контракт хука уже совпадает с будущим `EventSource`, поэтому при появлении SSE-эндпоинта `POST /ai-bots/:id/chat` страницы менять не потребуется.

## 7. Использование и логи

Компонент `BotUsageStats.tsx`:

- KPI: израсходованные токены и доля от лимита, число запросов за 14 дней, средняя задержка, стоимость;
- график запросов и токенов по дням (Recharts, `ComposedChart`);
- график средней задержки (`AreaChart`);
- таблица последних вызовов: время, пользователь, входные и выходные токены, задержка, стоимость, статус (`success`/`error`).

По правилам проекта каждый вызов LLM обязан попадать в `ai_logs` с полями `tenant_id`, `user_id`, `bot_id`, `model`, `tokens_in`, `tokens_out`, `latency_ms`, `cost`.

---

## 8. Страница `/settings/ai`

Упрощённая настройка одного агента: баланс токенов с цветовой индикацией (`emerald` до 50 %, `amber` до 80 %, `rose` выше), выбор модели, выбор режима, системный промпт, ползунок температуры, сохранение.
